VBSを使ったAccessフォームからVB6への移行

結論：
VBSを使って、AccessフォームからVB6への移行作業を 一部自動化することはできます。 ただし、AccessフォームをVB6フォームへ そのまま完全変換することはできません。

VBSでできること

VBSでは、主に次の作業を自動化できます。

  • Accessフォームの定義をテキストファイルへ出力する
  • フォーム上のコントロール名、位置、サイズを取得する
  • レコードソースやコントロールソースを取得する
  • VB6の.frmファイルのひな形を生成する
  • AccessのテーブルデータをCSVなどへ出力する

Accessフォーム定義をVBSで出力する例

AccessのSaveAsText機能をVBSから呼び出し、 フォームの設計情報をテキストファイルとして出力します。 

Option Explicit

Const acForm = 2

Dim accessApp
Dim dbPath
Dim formName
Dim outputPath

dbPath = "C:\Work\Sample.accdb"
formName = "F_顧客入力"
outputPath = "C:\Work\F_顧客入力.txt"

Set accessApp = CreateObject("Access.Application")

accessApp.OpenCurrentDatabase dbPath

' Accessフォームの設計情報をテキスト出力
accessApp.SaveAsText acForm, formName, outputPath

accessApp.CloseCurrentDatabase
accessApp.Quit

Set accessApp = Nothing

WScript.Echo "フォーム定義を出力しました。"

このVBSを実行すると、Accessフォームの設定が 次のようなテキストとして出力されます。 

Begin Form
    RecordSource ="T_顧客"
    Width =12000

    Begin TextBox
        Name ="txt顧客名"
        ControlSource ="顧客名"
        Left =1200
        Top =600
        Width =3000
    End
End

VB6フォームのひな形への変換

出力したAccessフォーム定義を解析することで、 次のようなVB6フォームのコントロール定義を生成できます。 

Begin VB.TextBox txt顧客名
   Height          =   315
   Left            =   1200
   TabIndex        =   0
   Top             =   600
   Width           =   3000
End
AccessとVB6では、座標やサイズの扱い、コントロールの種類、 プロパティ名などが異なります。
そのため、単純な文字列置換だけではなく、 コントロールごとの変換処理が必要です。

コントロール一覧をCSVに出力する例

フォームから直接VB6の.frmファイルを作る前に、 コントロール情報をCSVへ出力して確認する方法もあります。 

Option Explicit

Const acDesign = 1
Const acForm = 2

Dim accessApp
Dim formObject
Dim ctl
Dim fso
Dim outputFile
Dim controlSource

Set accessApp = CreateObject("Access.Application")
Set fso = CreateObject("Scripting.FileSystemObject")

accessApp.OpenCurrentDatabase "C:\Work\Sample.accdb"

accessApp.DoCmd.OpenForm "F_顧客入力", acDesign

Set formObject = accessApp.Forms("F_顧客入力")

Set outputFile = fso.CreateTextFile( _
    "C:\Work\controls.csv", _
    True, _
    True _
)

outputFile.WriteLine _
    "コントロール名,種類,ControlSource,Left,Top,Width,Height"

For Each ctl In formObject.Controls

    controlSource = ""

    On Error Resume Next
    controlSource = ctl.ControlSource

    If Err.Number <> 0 Then
        controlSource = ""
        Err.Clear
    End If

    On Error GoTo 0

    outputFile.WriteLine _
        """" & ctl.Name & """," & _
        ctl.ControlType & "," & _
        """" & controlSource & """," & _
        ctl.Left & "," & _
        ctl.Top & "," & _
        ctl.Width & "," & _
        ctl.Height

Next

outputFile.Close

accessApp.DoCmd.Close acForm, "F_顧客入力"
accessApp.CloseCurrentDatabase
accessApp.Quit

Set outputFile = Nothing
Set formObject = Nothing
Set fso = Nothing
Set accessApp = Nothing

WScript.Echo "コントロール一覧を出力しました。"

出力されるCSVの例

コントロール名,種類,ControlSource,Left,Top,Width,Height
"txt顧客名",109,"顧客名",1200,600,3000,315
"txt住所",109,"住所",1200,1000,5000,315
"cmd登録",104,"",6500,5000,1500,500

完全自動化が難しい部分

VBSを使用しても、次の部分は通常、 手作業または個別の変換処理が必要です。

Access側の機能 VB6側で必要になる対応
Access VBA VB6用のコードに書き換える
DoCmd.OpenForm Form.Showなどへ変更する
Me!コントロール名 VB6のコントロール参照形式へ変更する
DLookup、DCount SQL、DAOまたはADOの処理へ置き換える
サブフォーム 別フォームやグリッドなどで再構築する
コンボボックスのRowSource ADOなどで一覧データを読み込む
条件付き書式 VB6のイベント処理で再現する
Accessマクロ VB6コードとして再実装する
Accessレポート DataReportや別の帳票機能で作り直す

現実的な移行方法

  1. VBSでAccessフォームの設計情報を出力する
  2. コントロール名、種類、位置、サイズを取得する
  3. AccessとVB6のコントロール対応表を作る
  4. VBSでVB6の.frmファイルのひな形を生成する
  5. VB6でフォームを開き、配置を調整する
  6. Access VBAをVB6用に書き換える
  7. DAOまたはADOでデータベース接続処理を実装する
  8. 動作確認を行い、Access固有機能を個別に修正する
VBSでフォーム情報を抽出し、VB6フォームのひな形を 自動生成した後、処理部分を手作業で仕上げる方法が現実的です。

向いているAccessフォーム

次のような比較的単純なフォームであれば、 VBSによる自動変換の効果が期待できます。

  • テキストボックスが中心の入力フォーム
  • ラベル、ボタン、コンボボックスが中心のフォーム
  • 単票形式のマスタ登録画面
  • 単純な検索・一覧画面
  • 複雑なサブフォームや条件付き書式が少ない画面

移行が難しくなりやすいフォーム

  • 複数のサブフォームを使用している
  • Access VBAのコード量が多い
  • Accessマクロに強く依存している
  • 複雑な集計クエリを使用している
  • 条件付き書式や動的な画面制御が多い
  • Accessレポートと密接に連動している
最終的な整理

VBSを使えば、Accessフォームのコントロール情報を取得し、 VB6フォームのひな形を生成できます。

ただし、AccessのVBA、マクロ、サブフォーム、 クエリとの連動などは、VB6向けに個別に作り直す必要があります。
