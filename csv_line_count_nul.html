CSVの行数をBATで数える
NULを含む場合の回避案

前回提示した、findを使わずに目印の行番号を取得する方法です。PowerShell・VBS・追加ソフトは使いません。

作成日：2026年11月10日（日本時間） ／ v1.0
BAT + Windows標準コマンド元CSVへの書き込みなしWindows実行・実データ検証は未実施
最初に：実データで正しい件数との照合が必要です。

現在のBATとCSVは未確認で、このコードもWindows上では実行検証していません。「NULL」が実際のNULバイト（0x00）なのかも未確認です。倍になる原因が特定できた、または解決済みという意味ではありません。まず、正しい行数が分かっている小さなCSVで試してください。

01使い方

  1. 下の「BATを保存」を押し、csv_line_count_nul.batを保存します。コードをコピーして作成しても構いません。
  2. メモ帳などでBATを開き、set "CSV_FILE=C:\work\data.csv"のパスを、対象CSVのフルパスに変更します。
  3. コマンドプロンプトからBATを実行し、表示されたRows=の数値を確認します。

例：BATを C:\work に置いた場合は、コマンドプロンプトで次を実行します。画面を残して確認できるよう、ダブルクリックではなくコマンドプロンプトから実行してください。

"C:\work\csv_line_count_nul.bat"

保存ボタンのBATは英数字のみ・BOMなし・CRLFです。日本語のパスへ書き換える場合は、実行環境のコードページと保存時の文字コードを合わせてください。日本語Windowsの一般的なCP932環境ではANSI（CP932）で保存します。CSV自体の文字コードとは別です。

02BATコード

変更箇所は冒頭のCSV_FILEです。ヘッダーと空行も含む、物理的な行数を数える想定です。

csv_line_count_nul.bat
@echo off
setlocal EnableExtensions DisableDelayedExpansion

set "CSV_FILE=C:\work\data.csv"

if not exist "%CSV_FILE%" (
    echo ERROR: File not found.
    exit /b 1
)

rem Empty file
for %%F in ("%CSV_FILE%") do if %%~zF EQU 0 (
    echo Rows=0
    exit /b 0
)

set "COUNT="

rem Add markers to the command output only, not to the CSV.
rem Read only the first marker's line number.
for /f "tokens=1 delims=:" %%N in ('^(findstr /n "^" "%CSV_FILE%" ^&^& echo __CSV_COUNT_END__^&^& echo __CSV_COUNT_END__^) ^| findstr /n /x /l /c:"__CSV_COUNT_END__"') do (
    if not defined COUNT set /a "COUNT=%%N-1" >nul
)

if not defined COUNT (
    echo ERROR: Could not determine the line count.
    exit /b 1
)

echo Rows=%COUNT%

endlocal

表示例：Rows=101。これは表示形式の例であり、実行テストの結果ではありません。空のファイルではRows=0を表示する分岐を設けています。

ヘッダー1行を除外する場合

ヘッダーが必ず1行あるときだけ、最後のecho Rows=%COUNT%の直前に次の処理を追加します。

rem Insert immediately before: echo Rows=%COUNT%
if %COUNT% GTR 0 set /a "COUNT-=1" >nul

03処理の考え方

CSVをfindstrで読み取り、全行に番号を付ける
→ 出力の末尾に目印を2行付ける
→ 目印だけを取り出して、その行番号 − 1 を取得する

最初のfindstr /n "^"は、各行の先頭に1:のような番号を付けます。後段のfindstr /n /x /lは、目印と完全一致する行だけを取り出します。/nは行番号、/xは行全体の一致を指定します。[1]

for /fにはCSV本文を渡さず、目印の行番号だけを渡す設計です。tokens=1 delims=:で、コロンより前の番号を取得します。[2] 元CSVへ追記する処理はありません。

目印を2回出すのは、最終行に改行がなく、1つ目の目印が最終行へつながる場合にも備えるためです。CSV本文には先に番号を付けるので、本文中に同じ目印の文字列があっても、そのままの目印行とは区別する設計です。

これは処理意図の説明です。NULを含む実ファイルでこの意図どおり動作することは未確認です。

04前提・制約

項目この回避案での扱い
想定するCSVShift-JIS（CP932）またはUTF-8、CRLFまたはLF改行。実データでの確認を前提とします。
行の長さ前回案と同じく、1行8,000バイト以下を対象範囲とします。この範囲内なら必ず成功するという保証ではありません。
対象外UTF-16・UTF-32、CRのみの改行、長大な行、任意のバイナリデータ。これらを汎用的に処理するコードではありません。
「NULL」の意味文字列のNULL、空欄の,,、実際のNULバイト0x00は別物です。データベースのNULLがCSVへどう出力されているかは未確認です。
行数とデータ件数CSVの引用符で囲まれた項目に改行がある場合、物理行数とデータ件数は一致しません。このBATはCSVの引用符構造を解析しません。[3]
エラーが出た場合File not foundは指定先を確認してください。Could not determine the line countやfindstrのエラー、既知の件数との不一致がある場合は、その結果を採用しないでください。

最低限の確認

同じ出力元で作った「NULLがない少量データ」と「NULLがある少量データ」の双方を、あらかじめ分かっている件数と比較してください。ヘッダーの有無、空行、最終行の改行の有無も確認対象です。確認が済むまでは、本番処理の件数判定に組み込まないでください。
