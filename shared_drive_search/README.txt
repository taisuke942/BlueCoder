今回の変更（v3.2）
・「新しく検索」「続きから検索」は自動再開を有効にして実行します。
  約4分ごとに進捗を保存し、1分以上待ってから次の処理を自動で開始します。
  実際の開始時刻はGoogle側の実行タイミングにより遅れる場合があります。
  毎回「続きから検索」を押す必要はありません。
・D1:F1に【未完了】自動再開待ちと、次に開始できる最も早い時刻を表示します。
・一時停止は予約を取り消して進捗を保持し、続きから検索で自動再開を再び有効にします。
  終了は予約を取り消し、その検索は再開不可です。表示済み結果は残します。
・完了・エラー・条件変更でも自動再開を止めます。エラーの無限再試行はしません。
・手動で約4分ぶんだけ実行する「手動で1回分だけ再開」も使えます。
・v3.xからはCode.gsの全文を更新します。FolderPicker.htmlと既存ボタン名は同じです。
  最初の手動実行で、自動実行の予約に必要な追加のGoogle権限を許可してください。
・状態表示欄が設定済みならsetupDriveSearchの再実行は不要です。
・日時表示のtimeZone引数エラー対策は引き継いでいます。シートのタイムゾーンが
  使えない場合は日本時間（UTC+9）と明示し、日時の整形エラーで検索を止めません。

状態表示（v3.1から継続）
・シート上部のD1:F1に、状態・件数・次の操作・日時の4項目を、大きく常時表示します。
・緑の【検索完了】だけが、対象全体を最後まで検索した状態です。
・青は【未完了】検索中、黄は【未完了】自動再開待ち・手動一時停止、
  赤は【未完了】終了・エラー・予期しない中断などを示します。
・確認件数と該当件数を表示します。自動再開待ちは「次の開始目安」、それ以外の
  未完了時は「状態の保存日時」、完了時は「完了日時」を表示します。
  旧版で日時が未記録なら「記録なし」と表示します。
  完了前の件数は途中結果です。総数が事前に分からないため％は表示しません。
  状態欄の日時は通常シートのタイムゾーンに従い、利用できない場合は日本時間と明示します。
・「状態を更新」で、Drive検索を始めずに保存済みの状態を表示し直せます。
・B1・B2の編集や選択画面による範囲変更では、自動再開を止め、条件変更として表示します。
  以前の結果が、現在の条件で検索した結果ではないことを明示します。

完了の判断
Apps Scriptの「実行が完了しました」は、1回分の実行が終わったという意味です。
約4分で区切って自動再開を待つ場合も、その回の実行自体は終了します。
検索全体の完了は、シート上の緑の【検索完了】で判断してください。
黄色の【未完了】自動再開待ちならそのまま待ちます。
手動の一時停止中なら、「続きから検索」で自動再開を再び有効にします。
新しい検索を開始できなかった場合は、前回の緑表示を赤いエラー表示へ切り替えます。
残っている前回の行を、今回の条件で検索が完了した結果として扱わないでください。

状態表示はD1:F1に残り、上の3行を固定するため、結果をスクロールしても確認できます。
図形ボタンはG列以降などへ置き、D1:F1に重ねないでください。

導入・更新
1. 現在の検索が停止した状態で、スプレッドシートの
   「拡張機能 → Apps Script」を開きます。
2. 現在の DRIVE_ID と、変更している場合は SHEET_NAME を控えます。
3. 共有ドライブ検索用のGASを、この版の Code.gs 全文へ置き換えます。
   控えた DRIVE_ID と SHEET_NAME を引き継ぎます。
   DRIVE_ID は初期位置と、先頭が / 1つの相対パス入力の起点です。
   上位の共有ドライブ一覧のために、新しいIDへ変更する必要はありません。
4. v3の FolderPicker.html はそのまま使えます。
   初回導入またはv2以前から更新する場合は、同梱の全文を設定してください。
   初めて追加するときは「ファイル」の「＋ → HTML」から名前を
   FolderPicker にして作成します。大文字・小文字を合わせてください。
5. Google Drive API v3（識別子 Drive）は既存設定をそのまま使います。
   未追加の場合は「サービス」の「＋」から追加します。
6. v3.1以降で状態欄が設定済みなら、setupDriveSearchの再実行は不要です。
   保存後にシートを再読み込みするか、「状態を更新」を実行します。
   初回などで状態欄が未設定の場合は、E1・F1の別データを他のセルへ移し、
   setupDriveSearchを1回実行します。D1:F1を結合し、1行目を112pxにして
   状態表示欄を作成します。上の3行を固定します。
   v2・v3の配置（B1/B2、見出し3行目、結果4行目）なら入力と既存結果を保持します。
   v1の旧見出しを検出した場合は、旧結果を消して現在の配置へ移行します。
7. スプレッドシートを再読み込みします。
   v3.xで保存した再開位置は、同じ条件・同じGoogleアカウントなら引き継いで再開できます。
   v1・v2以前の途中経過は引き継がないため、「新しく検索」から開始します。
8. 更新後の最初の検索は、手動で1回実行してGoogleの追加権限を許可します。
   途中の検索を続ける場合は continueDriveSearch、新しく始める場合は startDriveSearch を、
   エディタまたはシートのボタン・メニューから実行してください。
   途中経過があり条件が同じなら、最初から検索し直す必要はありません。
   トリガーの手動設定、メールアドレスの転記、追加のドライブID設定は不要です。

同じ検索用関数や DRIVE_SEARCH を旧版と新版の両方に残さないでください。
別の用途のコードは保持します。独自の onOpen や onEdit がある場合は、
既存処理と、この版のメニュー・状態更新処理をそれぞれ1つの関数にまとめます。

ボタンへの割り当て
スプレッドシートの「挿入 → 図形描画」で図形を作成し、
図形の「スクリプトを割り当て」に次の関数名を入力します。
末尾の () は付けません。既存ボタンの割り当て名は変わりません。

  フォルダ選択       showFolderPicker
  新しく検索         startDriveSearch
  一時停止           pauseDriveSearch
  終了               stopDriveSearch
  続きから検索       continueDriveSearch
  状態を更新（任意）       refreshDriveSearchStatus
  手動で1回分だけ再開（任意） continueDriveSearchOnce

上部の「共有ドライブ検索」メニューからも同じ操作ができます。
autoContinueDriveSearch はコードが自動で予約・管理する内部処理です。
この関数はボタンに割り当てたり、手動でトリガー登録したりしないでください。

状態を更新する
「状態を更新」は、保存済みの状態と現在の実行状態を確認して表示し直す操作です。
新しいDrive検索は始めません。シートを開き直したときも状態を確認します。
検索が動いていないのに「検索中」が残っていた場合は、中断として表示します。
最後のページまで保存済みでも完了確定前に中断した場合は、「続きから検索」で最終確認します。
強制終了や予期しない中断の後も、実行が止まったことを確認してから状態を更新できます。

一時停止と終了の違い
  一時停止：自動再開の予約を取り消し、現在のページ処理の区切りで止まります。
            途中結果と再開位置を保持し、「続きから検索」で自動再開を再び有効にできます。
  終了    ：自動再開の予約を取り消し、現在のページ処理の区切りで終了します。
            表示済み結果は残しますが、
            その検索を途中から再開することはできません。
            全体の検索は未完了なので赤色表示です。再検索は「新しく検索」を使います。

どちらも停止要求を受けて検索処理自身が止まる方式です。
実行中のDrive API通信を、その瞬間に打ち切る機能ではありません。
「要求」表示だけではまだ停止していないため、状態が一時停止・終了へ変わるまで待ちます。
終了要求の後で一時停止を押しても、終了要求を優先します。
操作は検索を開始したGoogleアカウントで行います。
ブラウザやPCを閉じてもGoogle側の自動実行は続きます。
止めたいときは「一時停止」または「検索を終了」を実行してください。

手動で1回分だけ再開する場合
「手動で1回分だけ再開」（continueDriveSearchOnce）は、保存済み位置から約4分ぶんだけ
実行します。続きが残っても次回の自動実行を予約しません。
「続きから検索」（continueDriveSearch）を使うと、自動再開へ戻れます。

Google側の実行そのものを強制終了する場合
Apps Scriptの実行一覧（「実行数」またはMy Executions）を開き、
対象の「実行中 / Running」の行の「その他 / ⋮」から
「終了 / Terminate」を選びます。
自動実行中の関数名は autoContinueDriveSearch です。手動実行時は startDriveSearch、
continueDriveSearch、continueDriveSearchOnce の該当する行を確認します。
強制終了は処理途中で打ち切るため、終了時の表示更新が行われない場合があります。
実行が止まったことを確認後、「状態を更新」またはシートを開き直して表示を確認します。
強制終了後に必ず自動復旧する仕組みはないため、再開する場合は「続きから検索」を使います。
自動再開の予約も止める場合は、シートの「一時停止」または「検索を終了」を実行します。
公式説明：https://developers.google.com/apps-script/guides/dashboard

シートの配置
  B1          名前に含まれる文字列
  B2          検索する場所
  D1:F1       結合した常時表示欄（状態、件数、次の操作、日時または次の開始目安）
  A3:F3       見出し
  A4:F以降    検索結果

共有ドライブ一覧について
この版は、個別の共有ドライブの上位に「共有ドライブ一覧」を表示します。
一覧は複数の共有ドライブを並べるアプリ内の入口なので、通常の親フォルダとして
新しいIDを指定する必要はありません。
「マイドライブ」「共有アイテム」は別の場所で、この版の対象には含みません。

場所を画面から選ぶ
1. 「フォルダ選択」を押します。B2で指定している場所から開きます。
2. 「ドライブ一覧」で一番上の一覧へ移動できます。
   共有ドライブの直下で「上へ」を押しても一覧へ戻れます。
3. ドライブやフォルダの名前をクリックして、その場所を開きます。
4. 目的の場所で選択ボタンを押すとB2に入り、画面が閉じます。
   一覧で「すべての共有ドライブを選択」も使えます。
5. B1へ検索語を入力し、「新しく検索」を押します。

B2の手入力例
  //                       共有ドライブ一覧で取得される全ドライブ
  //営業用ドライブ          名前が「営業用ドライブ」の共有ドライブ全体
  //営業用ドライブ/見積     そのドライブの「見積」と下位の全階層
  /                        設定した DRIVE_ID の共有ドライブ全体
  /営業/見積               設定した DRIVE_ID を起点に「営業 → 見積」
  GoogleドライブのフォルダURL
                           URLが指す共有ドライブ内フォルダと下位階層
  id:フォルダID            IDで正確に指定

画面から選択すると、共有ドライブ名を含む //ドライブ名/... の形で表示します。
手入力パス、URL、IDも、新規検索の開始時に確認済みのパス表示へそろえます。
同名ドライブや同じ親の中の同名フォルダがある場合は、画面またはURL・IDで指定します。
英数字などで10文字以上のフォルダ名は、/Documents2026 のように先頭へ / を付けます。
PCの G:\ などのドライブ文字は使いません。

検索と再開
・選択した範囲の下位階層にある名前を部分一致検索します。
・英字大小や全角半角は正規化します。本文検索・誤字補正・空白区切りの
  AND検索は行いません。ゴミ箱とショートカットのリンク先は対象外です。
・名前は取得して比較するため、対象件数に応じて時間がかかります。
・約4分を目安に保存し、次の1回分の自動実行を予約します。
  黄色の【未完了】自動再開待ちは、次の実行を待つ状態です。
  最低1分の間隔を置きますが、正確に1分後の実行を保証するものではありません。
・再開待ちの間はB1・B2や結果行を編集・並べ替えないでください。
  条件を変えたときは「新しく検索」を使います。
・処理用シートは自動作成して非表示にします。手動で編集・削除しないでください。
・Drive上のファイルは読み取り対象です。シートの入力表示・結果・進捗は更新します。
・APIのページトークンが失効した場合は「新しく検索」でやり直します。

自動再開の上限と、再開しない場合
・GASの通常の1回の実行上限は6分です。
・トリガーによる合計実行時間には、一般アカウントで1日90分、
  Google Workspaceで1日6時間の上限があります。自動でも無制限には実行できません。
  Googleの割り当ては変更される場合があります。
  https://developers.google.com/apps-script/guides/services/quotas
・開始時刻はGoogle側の実行タイミングにより遅れる場合があります。
  https://developers.google.com/apps-script/reference/script/clock-trigger-builder#afterdurationmilliseconds
・動かない場合は「状態を更新」で理由を確認します。手動一時停止、エラー、
  条件変更の後は、自動では続きません。追加権限をまだ許可していない場合や
  強制終了・予約失敗の後は、開始したアカウントで「続きから検索」を手動実行します。
  条件変更やページトークンの失効がある場合は「新しく検索」を使います。

日時表示のFAQ
・timeZone引数のエラーが出た場合は、Code.gsをこの版の全文へ更新し、
  「状態を更新」で確認します。
・日時の後ろの「日本時間」は、シートのタイムゾーンによる表示が使えず、
  日本時間の代替表示に切り替えた印です。原因の特定結果を示すものではありません。
・状態欄が設定済みなら、初回設定をやり直す必要はありません。

実環境での確認
ご利用のGoogleアカウントでの接続は、実際のDRIVE_IDを設定して確認してください。
